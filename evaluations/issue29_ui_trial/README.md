# Issue #29 第一轮自主 UI 试用证据（Forge，2026-10-21）

真实创作者路径：Chrome/Playwright 操作本机 Web UI（`./scripts/deeptalk ui`，127.0.0.1:8321），
非单元测试/API 直调。真实 B 站匿名检索共 10 次（含图片证据中的真实检索），
未触发平台限流；降透明复测使用 fetch 拦截桩验证纯前端状态机，不消耗真实配额。

## 实际体验摘要

- 正常路径：输入主题 → 回车/按钮提交 → 按钮与输入禁用 → 结果卡渲染（候选、播放量核验、UP、时间、来源）→ 完整可用。
- 异常路径：空主题即时提示；非法参考链接服务端优雅降级（结果区标注「已跳过：xxx（格式无法识别）」）；
  罕见词 0 候选时诚实输出「未强行凑数」并给改进建议；5 条链接上限正确（按钮转「已到 5 条上限」并禁用）；
  maxlength=200 浏览器原生强制。
- 可用性既有事实（非缺陷，未改动）：Enter 提交、aria-live/aria-label、按钮禁用态、结果滚动定位均已有实现。

## 发现的真实问题与修复（3 处，全部纯前端 index.html 单文件）

| # | 问题 | 级别 | 修复 |
|---|---|---|---|
| 1 | 慢检索无进度反馈：播放量逐条核验使检索耗时 20–80 秒，全程仅一条静态「正在检索…」，真实用户会以为卡死而重复提交或关闭页面 | P1 体验关键 | 状态文案逐秒显示已用秒数 + 时长预期 + 「请勿重复提交」；`document.title` 检索中加「检索中…」前缀，结束恢复 |
| 2 | 新一轮检索进行中，旧结果卡仍显示「检索完成」，与新检索状态矛盾，易误读为输入与结果不匹配 | P1 状态一致性 | 检索中给旧结果卡加 `stale` 类（opacity .55），完成后移除 |
| 3 | 窄屏（≤600px）布局：链接输入框被「移除」按钮挤压截断、移除按钮点击热区小；高视口下页脚悬空、空态头重脚轻 | P1/P2 | 移动端媒体查询：输入框整行、移除按钮右对齐 88×40 热区、搜索按钮全宽；桌面 footer 贴底（flex column + margin-top:auto）+ 空态表单垂直居中（`justify-content: safe center`，长内容自动回退顶部不裁切） |

判为非缺陷/不改（避免过度工程化）：非法 URL 前端拦截（服务端已优雅降级并说明）、
移除按钮 48px 标准（88×40 已够 Mac 本机工具场景）、输入框内长文本截断（单行输入固有行为）。
