# V0.4.1 Script Gate Hardening — Design

## Purpose

V0.4.1 fixes three correctness gaps in the V0.4 Script workflow without adding
new content-production features:

1. a failed Script Review check must constrain the machine gate;
2. a `reviewed` Script must be cryptographically and structurally linked to a
   valid, passing Review Artifact; and
3. Beat IDs must remain stable across user revisions.

The Script Draft and Script Review Artifact major versions remain `0.4`.

## Check-to-issue-to-gate contract

The reviewer still returns all 15 named checks and an issue list. The validator
owns a versioned, deterministic mapping from every check to permitted issue
types. A check with `outcome: fail` is valid only when its matching issue exists.

The eight safety-critical checks require a matching blocking issue:

| Check | Required blocking issue type |
| --- | --- |
| `factual_grounding` | `unsupported_fact` or `unverified_as_fact` |
| `attribution_integrity` | `attribution_error` |
| `uncertainty_preservation` | `material_uncertainty_loss` |
| `avoid_claim_compliance` | `avoid_claim_usage` |
| `high_risk_boundary` | `high_risk_overclaim` |
| `analysis_fact_separation` | `analysis_as_fact` |
| `perspective_fairness` | `perspective_distortion` |
| `research_gap_integrity` | `research_gap_filled` |

Editorial checks may fail with their mapped advisory issue and therefore may
leave the gate passing. No failed check may have no matching issue.
`not_applicable` is disallowed for every safety-critical check. It is allowed
only for `counterargument_fairness`, where the review must supply a reason.
The artifact is rejected (rather than guessed into a pass/fail state) if any of
these rules are violated. Gate status is then derived solely from the validated
issues: any blocking issue means `fail`.

## Review provenance contract

Every newly created Script Draft receives machine-owned `review_state`.
Writer and user-created revisions use the empty, non-review state. A passing
review produces a new revision with `status: reviewed` and a state containing:

- the Review Artifact ID;
- the reviewed source revision;
- `review_gate_status: pass`; and
- a SHA-256 digest of the reviewed script content.

The Review Artifact stores the same digest and remains bound to the Script ID,
source Script revision, Research Report ID, and Research Report revision.
Validation of a reviewed Script requires the matching Review Artifact and
recomputes the digest. The storage loader automatically finds that artifact
beside the Script JSON and fails closed if it is absent or mismatched. Merely
editing `status`, a review ID, or a gate string cannot create a valid reviewed
Script.

Failed reviews generate a new `draft` revision with no approval state. Any
content revision always resets review state to draft, so it needs a new review
before it can become reviewed again.

Existing V0.4.0 drafts remain loadable. A legacy `reviewed` Script without the
new linkage is deliberately not trusted: it must be re-reviewed.

## Stable Beat identity

Initial drafts receive `B001`, `B002`, and so on. Each draft also owns a
monotonic next Beat number and a record of retired IDs. On a user revision:

- an existing Beat may identify its predecessor with an optional revision-only
  `origin_beat_id`;
- the program validates that an origin exists and is used no more than once;
- retained Beats keep their predecessor IDs, including after moves or narration
  edits;
- newly inserted Beats receive fresh monotonically increasing IDs; and
- deleted IDs move to the retired set and are never assigned again.

The optional origin is accepted only as revision input and is not stored as
user-owned final identity. Where a predecessor is uniquely recognisable from
its structural grounding, the system may retain it automatically; ambiguous
matches must be explicit. The comparison tool continues to compare Beat IDs,
which now represents actual continuity rather than list position.

## Compatibility and scope

Validation supports legacy V0.4 drafts conservatively. New artifacts use the
new metadata even though their declared artifact version remains `0.4`.
This change does not introduce Material Search, Visual Assistance, video
generation, editing, captions, publishing, or external browsing by the writer
or reviewer.
