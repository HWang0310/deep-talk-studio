# DeepTalk Studio V0.3.1 Discovery Gate Hardening Design

## Goal

Harden the existing Topic Candidate Set 0.3 without adding a user-facing workflow: only actually inspected Codex Seeds may be `manual_open`, every saved machine-owned result must be reproducible, and the light Preflight must count distinct qualifying research directions conservatively.

## Design

`CodexInspectionManifest` is a companion input owned by the Skill, never by Raw Candidate JSON. It records the normalized URL, optional tool/reference ID and inspection time for pages the Skill actually opened. `prepare_codex_discovery()` accepts it; only matching URLs become `manual_open`, and all others stay `unmatched`.

A pure internal derivation layer receives raw candidate content, Seed provenance, generated time, category filter and the fixed rules. It deterministically derives Candidate IDs, seed status, time/Preflight eligibility, reasons, score, recommendation, display order, primary marker and aggregate counts. Both preparation and Candidate Set validation use this same layer; validation reconstructs the expected artifact and fails closed on any mismatch.

Preflight accepts only matched/manual-open qualifying Seeds. It normalizes URLs and conservatively groups duplicate URLs, same publisher and same host into one research direction. Time validation rejects inverted event time and timestamps more than five minutes after `generated_at`. Category diversity uses a two-pass display selection: first select no more than two per category, then fill remaining positions by ranking while still enforcing event-cluster de-duplication. The CLI removes its nonfunctional `--count` option and keeps the existing fixed maximum of five.

## Compatibility and Boundaries

Candidate Artifact stays at `0.3`; Research Report and FactCheck Artifact remain `0.2`. Existing saved V0.3 artifacts without an inspection manifest remain readable only if their provenance fields are reproducible under the new deterministic rules; no legacy data is silently trusted. No Script Agent, material, visual, editing or publishing capability is added.

## Testing and Evaluation

Regression tests cover manifests, tampering, preflight direction grouping, time consistency, two-pass category selection, fixed CLI behavior, raw-pool minimum and both Discovery-to-Research and direct Research paths. The real Broad, Tech/Business and Social/Public evaluations are rerun with the manifest. Their public summary uses `pass`, `fail` or `not_applicable` rather than claiming Top-5 behavior from a one-candidate result.
