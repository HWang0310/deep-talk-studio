# DeepTalk Studio V0.2 Design

## 状态与范围

本设计落实 ChatGPT 对 V0.1 的正式 Review，产品状态从 `Engineering Pass / Editorial Validation Pending` 推进到可复查的研究质量门槛。用户已经明确批准附件中的 V0.2 范围并要求直接实施。

V0.2 只建设 Research Quality Gate 与 Independent Fact Check，不实现 Topic Discovery、Script Agent、素材搜索、视觉生成、剪辑或发布。

## 方案比较与选择

考虑过三种实现：引入第三方 JSON Schema 库、为每个字段手写校验、以及在标准库内实现当前契约所需的递归 Schema 子集。项目保持 Python 3.9+ 和低依赖，因此选择第三种：Schema 继续是唯一结构契约，递归校验器执行 `type`、`required`、`enum`、数组、对象、`additionalProperties`、长度与数值边界，业务校验器执行 URL、唯一 ID、跨字段引用和状态门槛。这样不会削弱 Schema，也避免为当前规模增加运行依赖。

研究流程采用“同一提供器接口、两次独立调用”：Research Draft 和 Fact Check 使用不同 Prompt、不同 JSON Schema 和不同工件。Fact Check 必须包含新检索记录、反证检查和独立性判断；没有新检索的结果不能把报告升级为 `reviewed`。

## Research Report 0.2

报告新增稳定身份与历史字段：`report_id`、`revision`、`previous_revision`、`created_at`、`generated_at`、`research_mode`、`status`、`change_summary` 和 `corrections`。`report_id` 在同一报告的后续修订中保持不变，`revision` 递增；保存路径包含 ID 与修订号，已有文件绝不静默覆盖。

主张不再直接保存 `source_ids`。正式的 `evidence_links` 记录 `claim_id`、`source_id`、`relation`（`supports`、`contradicts`、`attributes`、`context`）、证据概述、定位信息、独立性分组和核查说明。Claim 新增 `importance`、`risk_level`、`risk_factors` 和 `verification_status`，高风险主张自动进入 Fact Check 队列。

Source 新增规范化 URL、检查方式、来源追踪方式、追踪匹配状态、追踪引用、独立性分组、独立性状态和转载指向。系统去除常见 tracking 参数，合并相同规范 URL、同一发布者和明确/高度疑似转载；无法确定时保留 `unknown`，不把数量误算成独立证据。

## Provenance

API 提供器按 OpenAI 官方 Web Search 文档请求 `include: ["web_search_call.action.sources"]`，并保留 `web_search_call`、`action.sources` 与 `url_citation` annotations。报告 URL 与真实工具来源按规范 URL对账：匹配则记录真实 call/citation ID，未匹配则标为 `unmatched`。只依赖未匹配来源的 `confirmed_fact` 会被降级，质量门槛失败。

Codex Skill 模式记录 `codex_web_open` / `codex_tool_result`，由 Skill 在打开页面后写入来源 URL 和可追踪引用。两种模式不伪装成同一种证明方式。报告只保存简短概述与 locator，不保存网页长文。

## Independent Fact Check

`FactCheckArtifact 0.2` 是独立 JSON 工件，包含被排队的 claim、新检索来源、新 evidence links、逐项 outcome、建议分类、反证摘要、来源独立性判断和核查说明。完整 API 流程为：

```text
Topic → Research Draft r1 → FactCheck Artifact → Reviewed/Draft Report r2
```

事实核查会优先处理 `high` / `critical` 风险主张，并检查当事方说法、评论、归责、声誉风险和快速变化信息。Fact Check 即使由同一模型完成，也必须是第二次调用；没有 `searched_new_sources=true` 的高风险检查不计入覆盖率。

## 质量指标与审批门槛

`quality_summary` 保存底层指标，不使用不可解释的神秘总分：主张来源覆盖率、高风险核查覆盖率、confirmed fact 独立来源覆盖率、来源类型数、重复/转载数、未解决高风险数、无来源归因数和 provenance 匹配率。

第一版 Gate 采用公开阈值：主张来源覆盖率至少 80%，高风险核查覆盖率 100%，confirmed fact 独立来源覆盖率至少 80%，provenance 匹配率至少 80%，来源类型至少两类，且未解决高风险与无来源归因均为 0。未通过仍可保存为 `draft`，不能成为 `reviewed` 或 `ready_for_script`。

`approval_gate` 只实现当前需要的人工确认：普通 reviewed 报告在未来进入 Script Agent 前需用户一次确认；存在高风险 claim 时必须明确展示其 ID 后再确认。V0.2 不调用 Script Agent。

## 兼容、错误与测试

V0.1 JSON 可确定性迁移到 0.2：旧 source 标为迁移且未重新检查，旧 `source_ids` 转为 Evidence Links，旧内嵌 fact-check 不能冒充独立复核，状态保持 `draft`。CLI 支持显式迁移，并在 build/validate 时兼容读取。

所有入口最终调用同一递归 Schema 和业务校验。任何 JSON、嵌套字段、枚举、未知字段、URL 或引用错误都转成中文 `ReportValidationError`；CLI 返回简短错误，不显示 traceback。

测试采用标准库 `unittest`，按红—绿循环覆盖 Schema、Evidence、去重、provenance、独立 Fact Check、质量门槛、历史保存、迁移和 CLI 错误。三个真实事件完整报告留在被忽略的 `reports/`，仓库只提交方法、无敏感内容的汇总指标与测试。

## 设计自检

- 无 `TBD` 或未决占位符。
- 报告状态、质量 Gate 与用户审批三者职责分开。
- 保持 Python 3.9+ 和标准库核心。
- V0.2 范围没有提前进入 Topic Discovery 或 Script Agent。
- OpenAI provenance 字段与 2026-08-10 官方文档一致。
