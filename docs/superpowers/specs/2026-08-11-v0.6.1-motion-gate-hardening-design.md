# DeepTalk Studio V0.6.1 Motion Semantics & Production Gate Hardening 设计

状态：ChatGPT 已完成 V0.6.0 Review 并明确要求实施；本版是 V0.6 的收口版本，不进入 V0.7。

## 目标与边界

V0.6.1 让 timeline、bar、comparison、diagram 真正按内部语义分步运动，同时封闭 Display Text、Production QA 和 PDF/document 三个生产 Gate。完成后再由 ChatGPT 正式验收 V0.6，并进入第一轮真实用户端到端试用。

本版不做字幕、BGM、音效、最终剪辑、标题、封面、发布、TTS 或音频对齐。

## 方案选择

采用“Python Core 结构化 `scene_payload` + 两个无事实判断 Adapter”的方案。Python Core 拥有数据、顺序、文字、Claim/Evidence 绑定和降级决定；Remotion 与 HyperFrames 消费完全相同的 payload，只实现逐元素时间语义。V0.5 SVG 仅保留为静态 fallback、调试或人工检查，不再充当四类 Motion 的动画主体。

没有选择让两个 renderer 解析 SVG，因为那会复制语义解析并产生跨引擎漂移。也没有选择预渲染帧序列，因为它会失去结构化可审计性，并显著增加产物体积。

## Scene Payload

Production Plan 0.6.1 的每个 scene 增加严格、可判别的 `scene_payload`。文字字段统一使用 Display Text 对象，包含 `text`、`origin`、`text_kind`、`claim_ids` 和 `evidence_link_ids`。payload 类型包括：

- `timeline`：按确定顺序保存事件；基线先出现，marker 再依次出现，日期和事件文字跟随对应 marker。
- `bar`：保存有序 data points；每根柱从共同基线增长，标签和值随后出现，并带稳定 stagger。
- `comparison`：保存至少两个有序条目；左右区域和条目分别进入，不把整张 SVG 当成一个元素。
- `diagram`：保存有序 nodes/edges；edge 只能在两个端点之后出现，edge label 与 edge 同步。
- `image`：只保存已通过 render boundary 的 PNG/JPEG/WebP，以及可选 capture region；只做轻推、平移或高亮。
- `aroll`：保存固定、中性的真人口播占位标签。

Renderer 不得补写 payload 没有的数据、文字、因果关系或顺序。遇到不支持的 payload，Python Core 生成 production gap，renderer 不做猜测式 fallback。

## Display Text Grounding

移除“没有数字即可视为 editorial”的规则。文字来源至少区分：

- `machine_editorial`：只允许版本化白名单中的固定短语，例如“发生了什么”“关键时间点”“两个解释”“真人口播”“辅助画面待补”。
- `research_fact`
- `research_attribution`
- `material_caption`
- `visual_label`

除白名单机器短语外，所有文字默认需要 Claim/Evidence 绑定，并且文字本身必须能够从绑定 Claim、批准 timeline 或已审结构化 Visual 字段中确定性回查。仅提供一个无关的合法 Claim ID 不算通过。无法证明“同样或更保守”的表达时，Core 不渲染该文字，改用白名单中性标签或生成 gap。

因果 diagram edge 采用最保守规则：edge label 必须由绑定 Claim 明确支持；“A 导致 B”一类因果语句若没有对应因果 Claim，必须在进入项目之前被拒绝或降级。

## Production QA 链路

所有外部命令结果统一为结构化 check：`check_name`、`renderer`、`exit_code`、`outcome`、`command_category`、安全摘要。Core 根据 check 结果确定性生成 issue，再由 issue 推导 Gate；调用方不能另传一份 package failure 清单。

- 环境失败 → `production_environment_unavailable`，包级阻断。
- 项目验证失败 → `renderer_validation_failed`，包级阻断。
- preview 失败 → `renderer_preview_failed`，包级阻断。
- HyperFrames 的 doctor/lint/validate/inspect 均是独立 typed check。
- Remotion 的 npm ci/lint/typecheck/compositions 均是独立 typed check。

任何 fail check 都必须对应 blocking issue，因此不可能出现“检查失败但 Gate 通过”。QA validator 会重新推导这条关系，拒绝篡改后的 artifact。

## PDF / Document Boundary

原始 PDF 只能保留为来源和 provenance，不能被复制进 renderer，也不能成为 CanvasImage 或 HTML img。Motion 只消费 V0.5 已登记、已审、带 SHA/尺寸/页码/区域信息的 PNG/JPEG/WebP capture。

PDF 没有安全 capture 时生成 gap：“文件已取得，但尚无可安全展示的页面截图。” 已批准截图可使用轻推、轻微平移和区域高亮，不做 OCR，不从图片中推导新事实。

## Renderer 语义

Remotion 使用 `useCurrentFrame()`、`interpolate()`、`Easing` 和必要时的 `spring()` 驱动 React/SVG 原子元素；禁止 CSS animation/transition。静态图片仍用 CanvasImage，但四类结构化 Motion 不用 CanvasImage 承载整张 Visual。

HyperFrames 先完成布局，再用 paused、同步、确定性的 GSAP timeline 注册动画；禁止随机、系统时间、无限 repeat 和异步 timeline。粗剪多场景使用入场覆盖式过渡，不在旧 scene 上追加不合法的提前退出动画。

## Rough Preview 与跨引擎证据

只有当 Manifest 中确实存在 MAPREVIEW 且 QA ready 时，用户摘要才写“粗剪视觉预览已生成”。否则写“粗剪视觉预览生成失败，但已有 X 个独立 Motion Clip 可用。”

跨引擎测试同时检查：同一 payload、独立元素数量、动画定义、生成项目结构和真实 MP4。公开 synthetic motion evidence 使用完全虚构、无版权风险的数据，至少展示一条 timeline 或一组 bar，并随 Release 提供 MP4 与 contact sheet。

## 评测

V0.6.1 固定覆盖 A–G：稳定商业 bar、争议事件 timeline、权利稀疏 diagram、comparison、PDF/capture 边界、QA 矛盾、Display Text 语义绕过。两个 renderer 还必须真实渲染同一份含 2–3 个内部元素的小 Plan。

## 失败与兼容策略

旧的 V0.6 Production Plan 不是长期存档接口；canonical Material Package 保持不变，需要时可确定性重新生成 0.6.1 Plan。所有输出继续不可覆盖，远端发布不改写 Git 历史。正常用户路径仍只运行选定 renderer，双引擎只用于评测与兼容证明。
