# DeepTalk Studio V0.3 Topic Discovery 设计

## 目标与边界

V0.3 增加模式 B：用户不知道今天讲什么时，系统在最近 72 小时的公开信息中寻找少量、可解释且有研究基础的深度口播候选题。用户只需选择编号，所选 Candidate 的结构化交接信息便进入既有 V0.2 Research Workflow。V0.3 不生成口播稿，不做素材、视频、剪辑或发布。

本设计以 ChatGPT 对 V0.2.1 的正式 Review 和 V0.3 验收任务为已经批准的产品规格；不会要求非工程用户重复进行技术设计确认。

## 方案选择

1. 只在一个巨大 Prompt 中要求模型找热点：开发快，但总分、去重和风险判断不可复查，不能采用。
2. 接入新闻数据库或热榜平台：覆盖面更大，但要引入账号、合规、稳定性和维护成本，超出 V0.3。
3. **版本化 Candidate Artifact + 轻量 Preflight + 确定性筛选与评分**：模型或 Codex 搜索工具提供候选和公开 Source Seeds；Python 负责资格 Gate、时间窗口、聚类、类别多样性、总分、存档和下游交接。这是本版采用的方案。

## 数据契约

新增 `Topic Candidate Set 0.3`，独立于 Research Report 0.2。每次发现生成不可覆盖的 JSON 与便于阅读的 Markdown，包含机器生成的 `discovery_id`、时间、窗口、Channel Profile 版本和排序候选。

候选的模型/Codex 内容只包括事件说明、时间、新鲜度等五项原始分与理由、Source Seeds、风险和事件键；它不得提交 `total_score`、推荐标签、资格结论、ID、时间或 Artifact 身份。代码以固定权重计算：researchability 30、depth_conflict 25、freshness 20、channel_fit 15、attention_signal 10。原始分范围 0–5，最终分是加权结果的确定性整数。

`source_seeds` 仅是研究入口，不是确认事实或 V0.2 Evidence Ledger。每条 Seed 记录 URL、发布者、日期、来源类型和用途。API 模式将其与 Web Search provenance 重新匹配；Codex 模式由 Skill 只在实际打开页面后写入 Seed。

## Preflight、Gate 与排序

Discovery 只做轻量 Preflight：推荐或备选题必须有可打开的 HTTP(S) Source Seeds、至少两个独立的研究方向、并至少有一个官方、原始、监管、公司或可靠媒体入口。没有资料、只依赖匿名传言或未证实指控的候选会被拒绝；重大而资料仍不足的快速事件会保留为 `watch`，但不挤入 Top 5。

代码接受以下时间规则：事件在 72 小时窗口内，或事件开始于最近 14 天且在 72 小时内有重要进展。超时事件被降为 `watch` 或 `rejected`，不能通过分数绕开。高风险（公共安全、法律、声誉、事故、伤亡、归责、政治／公共政策）且证据弱的候选同样降为 `watch`。

Event cluster key 将本质相同的新闻合并，只保留得分最高的一项。展示候选最多五项，每个类别默认最多两项；选择过程先按分数、再按稳定字段排序，因而可复现。Creator attention 只能作为可选 attention 的文字依据，不能作为事实证据；没有公开可用的 Creator 信号时照常运行，也不虚构播放量或热度数字。

## 使用路径

```text
模式 B 自然语言
→ discover-topics Skill / discover CLI
→ Topic Candidate Set 0.3（JSON + 简短 Markdown）
→ 用户回复“1”或“研究 1”
→ latest manifest 解析 Candidate
→ Research Handoff Brief 0.3
→ 原有 V0.2 Research Draft → Fact Check → Quality Gate

模式 A 用户直接给主题
→ 原有 V0.2 Research Workflow（不变）
```

`discoveries/` 保存历史 Candidate Artifact；同一个 discovery ID 永不覆盖。`discoveries/latest.json` 仅保存最新指针，支持用户只回复数字。真实发现结果保持 Git ignore，公开仓库只提交去内容化的评测汇总。

## 模块边界

- `config/channel-profile.json`：默认频道定位和版本化约束。
- `discovery.py`：原始候选补全、Preflight、评分、去重、多样性和 Research Handoff。
- `discovery_validation.py`：Candidate Artifact / Raw Candidate 的 Schema 与交叉字段验证。
- `discovery_storage.py`：历史保存、latest manifest 和选择读取。
- `discovery_renderer.py`：普通用户短卡片 Markdown，不输出整份 JSON。
- `providers`：为 OpenAI API 增加独立的 `discover()`；复用真实 Web Search provenance。
- `.agents/skills/discover-topics`：处理“今天讲什么”等自然语言，按公开页面进行 Preflight，并在用户回复编号后无重复提问地交给 `research-topic`。

## 验证

测试先于实现，覆盖 Artifact Schema、未知/缺失字段、固定权重、资格 Gate、72 小时及持续事件、陈旧事件、高风险弱证据、Seed URL、事件去重、类别多样性、Creator signal 缺失、历史/选择、CLI、API 以及模式 A 回归。发布前完成三种真实 Discovery 评测，并只提交去内容化结果。
