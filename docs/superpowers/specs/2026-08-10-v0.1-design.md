# DeepTalk Studio V0.1 设计说明

## 目标

V0.1 建立一个可长期维护的 AI 内容生产项目，并交付第一个可用的 Research Workflow。输入一个主题后，工作流搜集公开资料，区分事实、报道、当事人说法、评论和未证实信息，比较不同立场，最终保存可核查的研究底稿。

V0.1 不写口播稿、不复制任何创作者的表达，也不自动发布内容。未来 Script Agent 只能消费研究底稿中的结构化字段，不能把来源文章当作改写素材。

## 使用方式

首选入口是仓库级 Codex Skill。用户在本仓库中用自然语言提出“研究某个话题”，Codex 自动读取 `.agents/skills/research-topic/SKILL.md`，使用可用的联网搜索工具执行研究，并调用项目的确定性校验程序保存报告。该入口复用 Codex 当前登录状态，用户无需管理 API 密钥。

同时提供命令行入口，供未来自动化系统调用。配置 `OPENAI_API_KEY` 后，`./scripts/deeptalk research "主题"` 通过 OpenAI Responses API 的 `web_search` 工具生成相同格式的报告。没有密钥时，仍可运行示例、校验已有报告和全部测试。

## 架构

项目保持两层结构：

1. Agent/Skill 层负责需要判断力的工作：设计搜索策略、搜索网页、比较来源、形成观点与冲突。
2. Python 核心层负责稳定契约：数据模型、交叉引用校验、Markdown 渲染、JSON 保存、文件命名和 API 适配。

模块边界如下：

- `models.py`：报告字段和枚举，不依赖外部服务。
- `validation.py`：检查来源、事实引用和跨字段关系。
- `renderer.py`：把统一 JSON 转成适合阅读的中文 Markdown。
- `storage.py`：按日期和主题保存 Markdown/JSON 双格式文件。
- `prompt.py` 与 `schema.py`：定义研究约束和机器可读输出契约。
- `providers/openai.py`：唯一接触 OpenAI HTTP API 的适配器，可被未来其他提供器替换。
- `workflow.py`：串联提供器、校验、保存，不包含搜索细节。
- `.agents/skills/research-topic/`：Codex 可自动发现的研究工作流。

未来的 Topic Discovery、Fact Check、Perspective Analysis、Script Writing、Material Search、Visual Generation、Editing Plan 和 Publishing 都通过读取或产生版本化 JSON 工件连接，不直接耦合到 V0.1 的实现。

## 报告契约

每份报告同时保存 `.json` 和 `.md`。核心字段包括：

- 研究范围、摘要和时间线；
- 来源清单及来源类型、发布时间和可信度说明；
- 带分类与置信度的主张；
- 多方观点、观点冲突和未决问题；
- 可做内容的切入角度；
- 事实核查备注、局限性；
- 交给未来 Script Agent 的明确接口。

主张分类固定为：`confirmed_fact`、`media_report`、`party_statement`、`commentary`、`unverified`。任何 `confirmed_fact` 必须引用至少一个来源；所有引用 ID 必须存在；URL 必须为 HTTP(S)。这套约束优先保证可追溯，而不是假装 AI 能自动证明绝对真相。

## 研究原则

- 优先官方文件、当事方原始材料和可靠媒体，再补充专家、评论者与创作者观点。
- 对重要事实做多源交叉检查；来源数量不是可信度的替代品。
- 明确标注“谁说的”和“证据到哪一步”，不把转述当事实。
- 同时寻找支持、质疑和替代解释，主动记录冲突。
- 只做必要的短引用，主要使用自己的概括，保留可点击来源。
- 不抓取或重写他人完整稿件，不模仿具体创作者的独特表达。
- 对快速变化、高风险或证据不足的话题保留局限性和后续核查清单。

## 错误处理

- 主题为空：立即拒绝并给出中文提示。
- 未配置 API 密钥：命令行明确说明仍可在 Codex 中使用 Skill，或先配置密钥；不打印或保存密钥。
- API 网络或服务错误：保留简短、可操作的错误信息，不写出凭据。
- 模型输出不符合契约：不保存为正式报告，列出校验失败原因。
- 文件名冲突：同一主题同一天使用稳定路径覆盖，便于重跑；不同主题互不覆盖。

## 测试策略

使用 Python 标准库 `unittest`，避免安装依赖。单元测试覆盖模型解析、未知引用、事实缺少来源、Markdown 标签和路径安全；集成测试使用本地假提供器跑通“主题输入 → 校验 → Markdown/JSON 保存”。OpenAI 适配器使用受控传输函数验证请求和响应解析，不发真实付费请求。Skill 使用官方校验器检查结构，并用仓库测试验证其调用的报告构建链路。

## V0.1 完成边界

完成：指定主题研究、结构化报告、来源追踪、事实/观点区分、冲突与角度、Script Agent 交接字段、仓库级 Skill、离线示例、命令行和长期协作文档。

不完成：自动选题、独立的二次事实核查服务、口播稿、素材下载、视频生成、剪辑、发布、网页界面、账号体系和定时任务。
