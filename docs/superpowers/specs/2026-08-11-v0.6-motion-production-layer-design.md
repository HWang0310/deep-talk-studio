# DeepTalk Studio V0.6 Motion Production Layer 设计

状态：已由 ChatGPT 产品/架构 Review 明确批准，用户已要求立即实施。

## 目标与边界

V0.6 把 V0.5.1 已审素材包转换成可预览、可渲染、可直接拖入剪辑软件的 MP4/WebM 动画素材，并生成粗剪视觉预览、素材缺口和独立 Production QA。真人 A-roll 仍是主体；没有真人素材时只显示中性占位，不生成假主播、仿用户声音或最终成片。

本版不做字幕、BGM、音效、封面、标题 SEO、上传发布、运营分析或无人审核发布。

## 方案选择

采用“单一 Production Plan + 两个薄 Adapter”的架构。Python 核心拥有所有事实、权利、资产完整性、显示文字、场景语义、时长和 QA 判断；Remotion 与 HyperFrames 只消费同一份 JSON 并负责表现。普通工作流按确定性 `renderer_mode` 只渲染一套，评测才让同一个小计划同时经过两套引擎。

没有采用两套独立制作系统，因为那会复制事实和权利判断，长期容易让两个引擎显示不同数据。也没有采用只封装命令字符串的“假适配器”，因为本版验收要求真实 preview、lint/inspect 和 MP4 输出。

## 工件与数据流

```text
reviewed / reviewed_with_warnings Material Package path
→ V0.5.1 canonical loader 重放 r1 provenance → Review → r2
→ render-time asset integrity + display-text grounding
→ Production Plan 0.6（唯一机器接口）
→ deterministic renderer selection
→ RemotionRenderer 或 HyperFramesRenderer
→ immutable Motion Asset Manifest 0.6
→ Production QA Artifact 0.6
→ 用户简明结果 + rough visual preview + production gaps
```

Production Plan 绑定 Script、Material Package、Review ID、内容 digest 和 Production Profile。每个 Scene 绑定 Cue、Beat、素材/Visual、建议时长和结构化屏幕文字；`placement_anchor` 仍是口播原句而不是真实音频时间码。

## Python 核心模块

- `production_schema.py`：Production Plan、Motion Asset Manifest、Production QA 的严格 JSON 契约。
- `production_profile.py`：加载 `config/production-profile.json` 和 renderer 版本锁定。
- `production_validation.py`：正式输入 Gate、允许根目录、SHA-256/大小/MIME、reference-only 隔离、显示文字 grounding 和计划 binding。
- `production_planner.py`：从 Cue、ready assets、四类 Visual 确定性建立 Scenes、fallback 和 gaps；不让 renderer 补事实。
- `production_renderers/`：统一 `ProductionRenderer` 接口与 Remotion/HyperFrames 实现，集中执行外部命令、记录版本、退出码与摘要。
- `production_qa.py`：以真实文件和媒体探测结果推导 clip/package Gate；renderer 不可自报通过。
- `production_storage.py`：`production_packages/`、`production_assets/`、`production_projects/` 下不可覆盖保存。
- `production_workflow.py`：串联 canonical load → plan → selected adapter → QA → reading view。

## Scene 与显示文字

第一版支持 `timeline_motion`、`bar_motion`、`comparison_motion`、`diagram_motion`、`document_reveal`、`screenshot_pan`、`image_pan_zoom`、`text_explainer`、`transition_card` 和 `aroll_placeholder`。四类原创 Visual 使用结构化子项逐步建立；文件/截图只做轻推、平移和重点框；静态图片只做轻量 pan/zoom/crossfade。

屏幕文字使用结构化 `{text, text_kind, claim_ids, evidence_link_ids}`。编辑标题只能从保守白名单生成；事实文字必须绑定 Claim，数字和日期必须从绑定 Claim 或批准 timeline 确定性回查。无法证明的文字不会进入 renderer，而是成为 production gap。

## 资产与安全

每个进入 Composition 的文件在 adapter 之前重新检查：真实存在、位于显式 material asset root、大小和 SHA-256 一致、扩展名/MIME 合理、资格可用。Generated Visual 还必须是 `rendered + ready_to_use`。`reference_only`、`permission_required` 和 `rejected` 既不能复制到 renderer，也不能通过远程 URL 加载。

生产项目只由受控模板和经过校验的 JSON 生成；网络 HTML/JS 永不注入。输出路径由机器 ID 组成并解析到允许根目录，存在同名文件即拒绝覆盖。

## Renderer 实现

Remotion 模板锁定当前兼容版本，使用 `useCurrentFrame()`、内联 `interpolate()`、`staticFile()` 和结构化 props；不使用 CSS transition/animation。Studio 用 `--no-open` 验证，真实 render 产出 MP4 和 hero-frame still。

HyperFrames 模板通过正式 `npx hyperframes init --non-interactive` 建立。Adapter 先从 Production Profile 生成 `DESIGN.md`，再生成 HTML；HTML 使用正确 composition/clip data attributes，GSAP timeline 为 paused 并同步注册到 `window.__timelines`。正式顺序为 doctor → lint/validate → inspect → preview → render。

两套模板共享同一 Production Profile 生成的 colors、typography、safe area、spacing、motion intensity 和 attribution 样式。像素可不同，数据、文字、绑定、时长和场景目的必须相同。

## QA 与失败策略

包级 blocker（输入非 canonical、research update、计划 binding 错误）在 renderer 启动前停止。clip 级失败只隔离对应输出，其他安全 clip 可继续。QA 使用 ffprobe/文件摘要验证真实输出、1920×1080、30 fps、时长容差、非空、SHA-256、来源绑定和外部 URL 隔离；HyperFrames 额外记录 lint/inspect，Remotion 记录 Studio/build/render。

每个真实输出写入 Motion Asset Manifest，包括路径、格式、宽高、fps、时长、大小、SHA、source IDs、plan digest、renderer、命令摘要和 QA 状态。

## 测试与评测

单元测试覆盖输入、资产、显示文字、计划、renderer 选择、模板安全、不可覆盖和 QA。集成测试真实构建/渲染小型 fixture。正式评测包括 Stable Business、Contested Public、Rights Sparse、Blocked Input、Cross-renderer Compatibility 和 Asset Tampering；公开仓库仅提交去内容化摘要，不提交真实素材和视频。

## 自检

- 没有 TBD/TODO 或依赖用户技术选择的空白。
- Production Plan 是唯一语义接口；renderer 不拥有事实和权利判断。
- 普通工作流只选一个 renderer；双渲染只用于兼容性评测。
- 真实输出与用户内容目录全部 gitignored，公开仓库只保留模板、契约和虚构 fixture。
