# DeepTalk Studio V0.4 Original Script Agent Design

## Goal

Turn one explicitly approved Research Report 0.2 revision into an original, oral Chinese long-form video script with strict research grounding, a separate script-review pass, revision-safe storage, and a simple natural-language user experience.

V0.4 does not search for new facts and does not implement materials, visuals, editing, subtitles, thumbnails, publishing metadata, publishing, or creator-style imitation.

## Approved research boundary

Script work starts only when all of these fields agree:

- `status == ready_for_script`;
- `quality_summary.gate_status == pass`;
- `fact_check.status == completed`;
- `approval_gate.status == approved`;
- `approval_gate.ready_for_script == true`;
- `approval_gate.user_confirmation` is non-empty.

The user confirmation creates a new immutable Research Report revision. The approval revision changes only revision metadata, report status, and approval fields. It preserves sources, claims, evidence links, timeline, perspectives, conflicts, Fact Check, quality metrics, conclusions, and Script handoff content. A later normal research revision continues to reset approval.

## Script Profile 0.4

`config/script-profile.json` is the versioned default for Bilibili Chinese face-to-camera or narration-compatible deep commentary. It contains a 12-minute default, a conservative Chinese speaking-rate estimate, preferred oral/editorial traits, avoided report-like phrases, required structural capabilities, and originality boundaries.

The core parses explicit durations such as `8 分钟` or `15 分钟左右`, plus the coarse requests `做长一点` and `更紧凑一点`. Duration estimates are code-owned approximations, never model claims or real playback measurements.

## Script Draft Artifact 0.4

JSON is the machine interface. Markdown is derived for people.

Machine-owned fields include identity, revision, timestamps, report binding, mode, status, profile version, target duration, character count, duration estimate, beat IDs, and must-keep coverage. A model supplies only editorial content:

- working title, thesis, audience promise;
- structured beats with purpose, content kind, narration, claim/evidence links, analysis basis, and risk notes;
- closing, caveats, research gaps, and explained must-keep omissions.

Beat kinds are `fact`, `attribution`, `analysis`, `transition`, and `question`. Facts must use verified `confirmed_fact` claims. Party statements, media reports, and commentary must use attribution beats with matching evidence. Analysis must name its Research Claim basis and may not pose as a confirmed fact. Spoken text may not expose machine IDs.

The validator enforces report/revision binding, valid Claim and Evidence references, evidence-to-claim consistency, high-risk verification, fact/attribution boundaries, direct forbidden-claim reuse, machine-owned metrics, and deterministic must-keep coverage.

## Independent Script Review Artifact 0.4

Writer and reviewer are separate calls or Codex work steps. Neither receives a web-search tool. The reviewer compares only the approved Research Report and Script Draft.

The reviewer returns checks, issues, reasons, and fixes. Code owns review identity, issue IDs, severity, blocking count, gate status, and resulting Script status. Blocking issue types include unsupported fact, attribution error, avoid-claim use, unverified-as-fact, high-risk overclaim, material uncertainty loss, and analysis presented as fact.

No blocking issue permits a reviewed Script revision; any blocking issue keeps it draft. Editorial scores never override this gate and review is not publishing approval.

## Rendering and storage

Each Script revision is saved under ignored `script_drafts/YYYY/MM/DD/<report-id>/<script-id>/` as:

- canonical JSON;
- Editor Markdown with structure, beat kinds, references, caveats, gaps, risks, and duration estimate;
- Teleprompter Markdown containing only words intended to be spoken.

No revision is overwritten. Script-review artifacts are separate immutable JSON files. A latest pointer supports the normal user flow. Public Git contains only fictional examples and de-contented evaluation summaries.

## Revision and comparison

A user request such as “更紧凑一点”, “开头换一个”, or “缩到 8 分钟” produces a new Script revision bound to the exact same approved `report_id + report_revision`. Editorial content changes reset Script review status to draft. A changed Research revision can never be silently substituted.

Comparison reports changed, added, and removed beats; character and estimated-duration differences; and must-keep Claim coverage differences.

## API and Codex workflows

The OpenAI provider exposes structured Writer and Reviewer calls without `tools` or search provenance. Codex uses `.agents/skills/write-script/`, reads only the approved report, never searches, persists the exact user confirmation, records research gaps instead of inventing facts, and shows the Teleprompter version to the user.

Normal flow:

```text
reviewed Research r2
→ explicit user confirmation
→ approved Research r3
→ Script Writer
→ Script Draft r1
→ independent Script Review
→ reviewed Script or blocked draft
→ Teleprompter output
```

Mode A and Mode B already converge on the same Research Report contract, so both use this identical downstream flow.

## Validation and evaluation

Automated tests cover approval persistence, all Research and Script gates, model-owned-field rejection, grounding, review gating, duration, immutable storage, revision comparison, provider payloads, CLI errors, and old workflow regressions.

Three local evaluation scenarios are required:

1. stable technology/business approved report → complete Script;
2. contested public issue approved report → complete Script with fair counterargument and uncertainty;
3. draft or unapproved reviewed report → deterministic refusal.

The first two receive 1–5 human editorial scores for factual grounding, attribution, uncertainty, structure, oral naturalness, density, insight, counterargument fairness, originality, and usability. Full scripts remain ignored; only `evaluations/v0.4.0-summary.json` is public.

## Scope decision

The implementation remains one V0.4 release because approval, Script Draft, Script Review, and storage are one inseparable user workflow. It uses focused modules rather than a single large prompt or a generic multi-agent framework. V0.5 remains unstarted.
