# DeepTalk Studio V0.2.1 Quality Gate Hardening 设计

## 目标与边界

V0.2.1 只修正 V0.2 研究质量层的独立来源、API 输入所有权和 Fact Check 来源归组问题。正式 Research Report 继续使用 Schema 0.2，质量阈值不变；不实现 Topic Discovery、Script Agent、素材、视频、剪辑或发布功能。

## 设计

### 独立来源与质量指标

`confirmed_fact` 的独立确认只接受同时满足 `supports`、`provenance_status=matched`、`independence_status=independent` 且分组不同的来源。`unknown`、`related`、`syndicated`、`duplicate` 均不贡献独立确认数量。

质量审计同时收紧三处明显可刷高路径：纯 `context` 或未匹配来源不计入主张来源覆盖；未匹配来源的 `attributes` 不解除“无来源归属”；来源类型和 provenance 比率不由 duplicate / syndicated 记录抬高。阈值保持 V0.2 原值。

### API Research 草稿契约

新增内部 `API_RESEARCH_DRAFT_JSON_SCHEMA`。模型只生成研究内容；报告身份、revision、时间、状态、Fact Check、质量摘要、审批状态、来源规范化与 provenance、claim 核查状态和 Evidence review 标记均由 workflow 确定性生成。模型返回额外的 machine-owned 字段时，草稿 Schema 以 `additionalProperties=false` 拒绝。

### Fact Check 新来源归组

Fact Check 新来源先与原 Draft 来源合并，再统一执行 URL 规范化、追踪参数去除、重复 URL、同发布者、显式/标题转载和独立分组。系统覆盖模型填写的 `normalized_url`、`independence_group` 及 Evidence Link 分组；保存的 Artifact 和 reviewed report 都使用同一确定性结果。

## 数据流

```text
API research content
→ API_RESEARCH_DRAFT_JSON_SCHEMA
→ machine metadata + provenance reconciliation
→ Research Report 0.2 r1
→ Fact Check content + new provenance
→ combined deterministic source grouping
→ canonical FactCheck Artifact 0.2
→ Research Report 0.2 r2
→ hardened Quality Gate
```

## 验证

先增加会在 V0.2.0 旧逻辑下失败的回归测试，再逐项实现。完成后运行全部 unittest、示例、校验、Codex Draft、Fact Check review、迁移、修订防覆盖、Skill 校验、Python 3.9 语法兼容、干净环境安装、密钥扫描和三类真实评测。公开仓库只提交去内容化的 `evaluations/v0.2.1-summary.json`。
