# V0.4.1 Script Gate Hardening — Implementation Plan

> Execute this plan with test-driven development. The attached V0.4.1 product
> review is the approved design decision for this focused hardening release.

**Goal:** Make Script Review gating fail closed, make reviewed Scripts provable,
and preserve Beat identity across revisions.

**Architecture:** Add deterministic review consistency validation in the review
module, machine-owned review linkage in Script and Review artifacts, and
monotonic Beat identity allocation in the revision module. Keep artifact major
version `0.4` and preserve legacy drafts conservatively.

## 1. Add failing regression tests for review consistency

- Cover every critical failed check without its required blocking issue.
- Cover editorial failure with advisory issue, missing and duplicate checks, and
  invalid critical `not_applicable`.
- Run `python -m unittest tests.test_script_review` and confirm the new tests
  fail for the intended missing behavior.

## 2. Implement deterministic review consistency and gate derivation

- Add documented, versioned mappings for checks, issue types, and allowed N/A.
- Reject invalid artifacts before a reviewed revision can be produced.
- Add any narrow schema additions required for an editorial usability issue.
- Re-run the focused review tests.

## 3. Add failing review provenance tests

- Verify manual reviewed status, forged review metadata, mismatched review
  artifacts, and altered content fail validation/loading.
- Verify passing review creates valid reviewed r2; failed review creates draft.
- Verify a user revision resets review approval.

## 4. Implement review linkage and storage verification

- Add review-state metadata and deterministic script-content digest.
- Bind passing r2 to its matching Review Artifact.
- Make storage loading of a reviewed Script resolve and validate its artifact.
- Preserve legacy drafts while requiring legacy reviewed scripts to re-review.
- Re-run focused validation, storage, workflow, CLI, and review tests.

## 5. Add failing stable Beat identity tests

- Cover retained, inserted, deleted, moved, duplicate-origin, and unknown-origin
  Beats, plus comparison outcomes.

## 6. Implement monotonic Beat identity allocation

- Add revision-only origin input validation and code-owned active/retired ID
  state.
- Preserve retained Beat IDs, issue fresh IDs for inserts, and never reuse
  deleted IDs.
- Update prompts/skills and re-run revision/CLI tests.

## 7. Evaluate, document, verify, publish

- Re-run A/B/C V0.4 evaluations with controlled providers and add the synthetic
  fail-closed scenario; commit only decontented summary data.
- Update public docs, release notes, changelog, and handoff.
- Run the full suite, compileall, clean install, JSON checks, secret scan, and
  release tree/tag verification.
- Publish a non-force `v0.4.1` GitHub Release after confirming the public main
  tree is the expected V0.4.0 base.
