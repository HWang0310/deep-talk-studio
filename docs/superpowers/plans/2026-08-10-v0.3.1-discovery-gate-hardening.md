# DeepTalk Studio V0.3.1 Discovery Gate Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correctly harden V0.3 Discovery provenance, canonical validation, Preflight, time and display behavior without expanding product scope.

**Architecture:** Keep Topic Candidate Set at `0.3`. Extract deterministic candidate derivation so preparation and validation independently reconstruct the same machine-owned state. Use a separate Codex inspection manifest instead of allowing Raw Candidate content or mode selection to self-certify opening a source.

**Tech Stack:** Python 3.9+ standard library, unittest, existing JSON Schema subset, GitHub Releases.

## Global Constraints

- Do not add Script Agent, materials, visual generation, editing or publishing.
- Candidate Artifact remains `0.3`; Research Report and FactCheck Artifact remain `0.2`.
- Display maximum is fixed at five; do not retain a nonfunctional `--count` option.
- Only qualifying `matched` or manifest-backed `manual_open` Seeds count toward Preflight directions.
- Do not force-push or rewrite GitHub `main` history.
